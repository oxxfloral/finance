# OXX 통합 장부 (매출·매입 단일 구글시트) 계획

## Context
- 현재: 매출 시트(1DSWnL…), 매입 시트(1gaf4Z…)를 따로 수기 관리.
- 돈의 흐름: 신한은행 계좌 1개 + 우리카드 1개.
  - 매출: 대부분 계좌입금 + 세금계산서 발행. 소량은 매장 카드결제/계좌이체/현찰.
  - 매입: 우리카드 결제 + 현금. 현금은 계좌에서 30~50만원씩 인출 → 꽃시장에서 몇만원씩 나눠 지출(당일 다 쓰지 않음).
  - 매입 시트의 품목/단수/가격 → 단가 계산 → 3~4배수 참고해 L열 '소매가' 기입(참고치일 뿐 실제 판매가 아님).
- 목표: 한 스프레드시트에서 매출·매입·현금·증빙을 추적하고, 은행/카드 내역(엑셀 + 문자)과 대사해 누락을 잡는다.
- 레포 `oxxfloral/finance`는 비어 있음 → Apps Script 코드와 가이드를 여기에 커밋.

## 블로커 / 선행 확인
- 기존 두 시트의 실제 열 구조 확인 필요. Google Sheets/Drive 커넥터는 계정에 연결됐지만 이 세션에는 로드되지 않음 → **사용자 결정: 커넥터가 켜진 새 세션에서 이 계획으로 재시작.**
- 새 세션 첫 작업: Sheets 커넥터로 두 시트(매출 gid=1318104668, 매입 gid=1351770917)를 읽어 열 구조·행 수·합계 확인 → 이관 매핑 확정. (커넥터로 새 스프레드시트 생성/쓰기가 가능하면 탭 생성까지 직접 수행.)
- 신한 입출금 문자·우리카드 승인 문자, 은행/카드 엑셀 샘플(개인정보 가림)을 사용자에게 요청해 파서 형식 확정.

## 시트(탭) 구성 — 새 스프레드시트 "OXX 장부"
1. **거래원장** (모든 돈의 움직임 1행 = 1건)
   - 일자 · 구분(매출/매입/현금인출/현금입금/기타) · 결제수단(계좌/우리카드/현금/매장카드단말) · 거래처 · 적요 · 과세구분(과세/면세) · 공급가액 · 부가세 · 합계 · 증빙(세금계산서/계산서/카드전표/현금영수증/없음) · 증빙번호·발행일 · 출처(수기/SMS/은행엑셀/카드엑셀/이관) · 원본키(중복제거용) · 대사상태 · 메모
   - 현금인출은 비용이 아니라 '계좌→현금지갑 이동'으로 처리(손익 집계에서 제외).
2. **매입상세** — 도매상별 품목 라인. 기존 매입 시트 구조(품목·단수·가격·…·소매가 L열)를 그대로 유지 + `원장ID` 열로 거래원장의 매입 건과 연결. 단가=가격/단수, 3배·4배 참고가 수식 자동, 소매가는 수기 입력(참고치).
3. **현금지갑** — 현금 인출(+), 현금 매출(+), 현금 매입(−) 자동 집계 → 현재 보유 현금 잔액. '실사 금액' 입력 칸으로 장부 vs 실제 차이 표시(기록 누락 발견용).
4. **가져오기_신한** / **가져오기_우리카드** — 홈페이지 엑셀 내역을 그대로 붙여넣는 탭. 메뉴 실행 시 파싱 → 원본키(일자+시간+금액+적요 해시)로 중복 제거 → 거래원장에 추가, 규칙으로 자동 분류.
5. **SMS수신** — 휴대폰 자동화가 Apps Script 웹앱(doPost, 비밀토큰 검증)으로 보낸 문자 원문 저장 → 신한 입출금/우리카드 승인 문자 파싱 → 거래원장 추가(같은 원본키로 엑셀과 중복 방지, 엑셀이 들어오면 SMS 건을 '확인됨'으로 갱신).
6. **분류규칙** — 키워드(적요/가맹점명) → 거래처·구분·과세구분. 예: 'ATM','CD출금' → 현금인출; 거래처 입금자명 → 매출 거래처.
7. **대사** — 미처리 목록: 세금계산서 미발행 매출 입금, 상세 없는 카드 매입, 원장에 없는 SMS/엑셀 건, 현금지갑 차이.
8. **대시보드** — 월별 매출/매입/매출총이익, 결제수단별, 거래처 Top, 현금 잔액, 부가세 신고 참고(과세분 매출세액−매입세액; 생화는 면세일 수 있어 과세구분별로 분리 집계).
9. **설정** — 기본 배수(3/4), SMS 토큰, 계좌/카드 이름.

## 코드 (레포 구조)
```
apps-script/
  appsscript.json
  Menu.gs        // onOpen 메뉴: 초기설정, 기존시트 이관, 은행/카드 가져오기, 대사 갱신
  Setup.gs       // 탭·헤더·서식·데이터검증·대시보드 수식 생성 (멱등)
  Migrate.gs     // 기존 매출/매입 시트 ID를 읽어 거래원장·매입상세로 이관
  Parsers.gs     // 신한 엑셀행/우리카드 엑셀행/SMS 문자 파서 (순수 함수)
  Import.gs      // 가져오기 탭 → 원장, 중복제거(원본키), 분류규칙 적용
  Sms.gs         // doPost 웹앱 엔드포인트 + 토큰 검증
  Reconcile.gs   // 대사 탭/현금지갑 갱신
tests/parsers.test.js   // node로 Parsers.gs 단위 테스트 (실제 문자/엑셀 샘플 형식)
docs/설치가이드.md        // 새 시트 만들기 → 스크립트 붙여넣기 → 초기설정 → 이관
docs/SMS연동.md           // 아이폰 단축어 / 안드로이드(MacroDroid 등) 설정법
```
- 파서는 순수 함수로 작성해 Apps Script와 node 테스트 양쪽에서 동작.
- 문자/엑셀 형식은 실제 샘플(개인정보 가린 것) 받아서 맞춤.

## 진행 순서
1. 커넥터로 기존 두 시트 읽기 → 열 구조·데이터 범위 확인, 이관 매핑 확정.
2. Setup/Menu/Migrate 작성 → 이관 결과 건수·합계가 원본과 일치하는지 검증 함수 포함.
3. Parsers + Import (엑셀) → 샘플로 테스트.
4. Sms 웹앱 + 휴대폰 설정 가이드.
5. Reconcile + 대시보드.
6. 커밋 → `claude/peaceful-mccarthy-knqgqj` 브랜치에 push.

## 검증
- `node tests/parsers.test.js` : 신한/우리카드/SMS 샘플 파싱, 중복키 동일성 테스트.
- 이관 후: 원본 매출 합계·매입 합계·행 수 == 거래원장/매입상세 집계 (Migrate.gs의 검증 함수가 결과 표시).
- 같은 엑셀을 두 번 가져와도 원장 행 수 불변(멱등), SMS→엑셀 순서로 들어와도 중복 없음.
- 현금: 인출 40만 → 현금매입 3건 입력 → 현금지갑 잔액이 정확히 감소.
- (커넥터 쓰기 권한이 있으면) 새 시트를 직접 만들어 초기설정 결과 확인; 없으면 사용자가 가이드대로 실행 후 스크린샷 확인.
